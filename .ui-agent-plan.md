# Responsive Sidebar UX Proposal

## Summary

Transform the fixed 256px sidebar into a responsive navigation system: a permanent sidebar on large screens and a slide-in drawer with mobile header bar on smaller screens. The design maintains the existing dark theme aesthetic and feels native to the Spela brand.

---

## 1. Breakpoint Choice: `lg` (1024px)

**Rationale:** The existing codebase already uses `lg:` as the primary layout breakpoint for major structural changes (see `dashboard-page.tsx` line 353: `grid-cols-1 lg:grid-cols-3`, `game-detail-page.tsx` line 213: same pattern). The sidebar at 256px leaves only 512px of content at 768px (`md:`), which is cramped for game grids that start their multi-column layouts at `sm:` and `md:`. At `lg:` (1024px), the content area gets 768px — enough for the existing responsive grid patterns to work well.

- **Below `lg`:** Sidebar hidden, mobile header bar shown, drawer available
- **At `lg` and above:** Permanent sidebar, no mobile header, current behavior

---

## 2. Mobile Layout (below `lg`)

### 2a. Mobile Header Bar

A slim, fixed top bar replaces the sidebar on mobile. It provides orientation and menu access without taking excessive vertical space.

```
+--------------------------------------------------+
|  [=]   (Gamepad) Spela                           |
+--------------------------------------------------+
|                                                    |
|              Page content here                     |
|              (full-width, no left padding)          |
|                                                    |
+--------------------------------------------------+
```

**Specifications:**
- **Height:** 56px (`h-14`)
- **Background:** `bg-surface-950` — matches sidebar background for visual continuity
- **Border:** `border-b border-surface-800/50` — subtle separator, same as sidebar sections
- **Position:** `fixed top-0 left-0 right-0 z-40`
- **Content padding:** The main content gets `pt-14` on mobile instead of `pl-64`
- **Left side:** Hamburger button + logo icon + "Spela" text
- **Hamburger icon:** Three-line `Menu` icon from lucide-react, `h-5 w-5`, `text-surface-400 hover:text-surface-100`, inside a `p-2 rounded-lg` touch target (44px minimum)
- **Logo:** Same gradient icon (`Gamepad2`) and "Spela" text as the sidebar header, but slightly smaller to fit the bar

### 2b. Slide-in Drawer

When the hamburger button is tapped, the sidebar slides in from the left edge.

```
+----------+---------------------------------------+
|          |                                       |
| (Gamepad)|        Dimmed backdrop                |
|  Spela   |        (tap to close)                 |
|          |                                       |
| Dashboard|                                       |
| Library  |                                       |
| Stats    |                                       |
| Activity |                                       |
| ...      |                                       |
|          |                                       |
| [avatar] |                                       |
| username |                                       |
+----------+---------------------------------------+
```

**Specifications:**
- **Width:** Same `w-64` (256px) as the desktop sidebar — consistent, familiar
- **Position:** `fixed inset-y-0 left-0 z-50`
- **Entry animation:** `translate-x` from `-100%` to `0` with `transition-transform duration-300 ease-out` — smooth 300ms slide-in, matching the feel of native mobile drawers
- **Exit animation:** Reverse slide to `-100%` with `duration-200 ease-in` — slightly faster close feels more responsive
- **Content:** Identical sidebar content (logo header, nav links with icons/badges, user section at bottom). Same component, no duplication.

### 2c. Backdrop Overlay

- **Background:** `bg-black/50` — 50% black opacity. This matches the modal pattern in the codebase (`modal.tsx` uses `bg-black/60`), but slightly lighter since the drawer doesn't demand as much focus as a modal dialog.
- **Blur:** None. The modal uses `backdrop-blur-sm` but for a nav drawer covering the side, blur on the main content is distracting and computationally expensive on mobile. Keep it clean.
- **Entry:** `opacity-0` to `opacity-100` with `transition-opacity duration-300`
- **Exit:** `opacity-100` to `opacity-0` with `transition-opacity duration-200`
- **Position:** `fixed inset-0 z-40` (below the drawer at z-50)

## 3. Interaction Details

### Close triggers (all mandatory):
1. **Tap backdrop** — Standard. Click handler on the backdrop div.
2. **Escape key** — Standard. `useEffect` with `keydown` listener (same pattern as `modal.tsx`).
3. **Navigate** — Auto-close on any `NavLink` click. Use `useLocation` to detect route changes and close the drawer. This is essential — the user taps "Library", the drawer slides closed, and the Library page appears. No extra taps.

### Body scroll lock:
- When the drawer is open, set `document.body.style.overflow = "hidden"` — identical to the existing modal pattern (`modal.tsx` lines 40-49). Prevents background content from scrolling while interacting with the nav drawer.

### Swipe gesture:
- **Not included in this phase.** Swipe-to-open/close is a nice enhancement but adds complexity (touch event handling, velocity detection, partial-open states). The tap-based interactions cover all use cases well. Can be added later as polish.

### Focus management:
- When the drawer opens, focus the first nav link for keyboard accessibility
- When the drawer closes, focus returns to the hamburger button

## 4. Visual Design Details

### Mobile Header Bar
- Hamburger button: `p-2 -ml-1 rounded-lg text-surface-400 hover:text-surface-100 hover:bg-surface-800/50 transition-colors` — matches the logout button style in the sidebar
- Logo section: Same `Gamepad2` icon in the gradient box (slightly smaller, `h-8 w-8 rounded-lg`) + "Spela" text in `text-base font-bold text-surface-100`
- The header bar uses a subtle glass-like separation from the content below

### Drawer
- Visually identical to the current sidebar. Same background, same borders, same padding, same link styles. The drawer IS the sidebar — just with animated entry/exit.
- When open, the drawer casts a subtle shadow rightward: `shadow-2xl` for depth.

### Transitions
All transitions use CSS `transition` classes for GPU-accelerated performance:
- Drawer slide: `transform` property (GPU composited, no layout thrash)
- Backdrop fade: `opacity` property (GPU composited)
- Total animation: 300ms open, 200ms close. This asymmetry (slower open, faster close) is a standard mobile UX pattern — the user needs time to perceive the drawer appearing, but wants it to disappear quickly when dismissed.

## 5. Implementation Approach

### State management
- Add `useState<boolean>` for `isMobileMenuOpen` in `app-layout.tsx`
- Pass `onClose` callback to the sidebar for mobile mode
- Use `useLocation` to auto-close on navigation

### Files to modify

1. **`web/src/components/ui/sidebar.tsx`**
   - Accept new props: `mobileOpen`, `onClose`
   - On desktop (`lg:` and above): render as-is (permanent, fixed)
   - On mobile (below `lg:`): render as a drawer with backdrop when `mobileOpen` is true
   - The sidebar content itself is shared — no duplication

2. **`web/src/components/app-layout.tsx`**
   - Add mobile menu state
   - Render a mobile header bar (visible below `lg:`, hidden at `lg:` and above)
   - Pass mobile state to `Sidebar`
   - Change content padding: `pl-64` only at `lg:` and above; `pt-14` below `lg:`
   - Add `useLocation` effect to close menu on navigation

### No new files needed
The mobile header bar is small enough to live inside `app-layout.tsx` or as a private component there. The drawer behavior is added to the existing `Sidebar` component. This keeps the change focused and avoids file bloat.

---

## 6. Accessibility

- Drawer uses `role="dialog"` and `aria-modal="true"` when open
- Hamburger button has `aria-label="Open navigation menu"` and `aria-expanded` reflecting state
- Escape key closes the drawer
- Focus trap inside the drawer when open (focus the nav, return focus to hamburger on close)
- Backdrop click closes the drawer
- All existing keyboard navigation within nav links is preserved
