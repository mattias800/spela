# Improvements

Append-only log of potential improvements spotted during development.
Each entry includes the date, area, and a brief description. Used as
input for planning and prioritization.

Format: `- YYYY-MM-DD [area] Description`

Areas: `server`, `web`, `player`, `infra`, `ux`, `testing`, `docs`, `architecture`

---

- 2026-03-20 [player] ConsoleScreen.kt has many unused imports (AnimatedVisibility, expandVertically, fadeIn, fadeOut, shrinkVertically, CircleShape, Column, Row, items, Check, Close, Search, SwapVert, DropdownMenu, DropdownMenuItem, mutableStateOf, rememberSaveable, FocusRequester, focusRequester, Role, role, semantics, SpSearchField, ConsoleGenreBreakdown, GameGridItem, SpTypography). These should be cleaned up.
- 2026-03-20 [player] SecondaryArtPage.kt and SecondaryScreenContent.kt still use `consoleId.uppercase()` for console labels — should be reviewed to determine if those contexts are genuinely space-constrained or should also use `consoleName`.
- 2026-03-20 [player] ConsoleShowcaseSections.kt — all four section composables (ConsoleEssentials, ConsoleHiddenGems, ConsoleTopDevelopers, ConsoleRecentlyPlayed) add `.padding(horizontal = SpSpacing.ScreenHorizontal)` on their root modifier. This violates the "components never control their own outer spacing" principle. The parent (ConsoleScreen) should control horizontal padding instead.
- 2026-04-10 [architecture] Move `recordSecurityEvent` from `server/internal/api/security_event_recorder.go` to `server/internal/db` so non-HTTP call sites (background jobs, WebSocket auth handlers, future netplay session auth) can emit events without depending on gin. The gin-aware `recordSecurityEventCtx` wrapper should stay in `internal/api`. Flagged by code-reviewer during PR #357 review.
- 2026-04-10 [web] Admin sidebar (`web/src/components/app-layout.tsx`) now has 11 items and is starting to feel cramped after adding Security Events. Consider sub-grouping into "Content" (Upload/Scan/Metadata/Cheats/ROM Hacks/BIOS) and "System" (Users/Settings/Core Compatibility/Security Events). Flagged by ui-agent during PR #357 review.
- 2026-04-10 [web] `/admin/security-events` detail modal should offer "View all events from this IP" / "View all events for this user" follow-up actions — the single most useful operation during an investigation is pivoting by IP or username. Would set the relevant URL query filter and close the modal. Flagged by ui-agent during PR #357 review.
- 2026-04-10 [server] `GET /api/admin/security-events` has no response size cap or server-side default `since` window. When the `security_events` table grows large, an unfiltered `Count(*)` over all rows will be slow on SQLite. Consider: default `since` to `30d` server-side when no `since` is supplied, and/or skip the full count when `total > 10_000` and return a `hasMore` boolean flag on the last page. Flagged by code-reviewer during PR #357 review.
- 2026-04-10 [server] `GET /api/admin/security-events` accepts raw free-text `ip` filter without format validation. Admin-only so not a security issue, but a typo like `10.o.0.1` silently returns zero results with no feedback. Validate it parses as an IP or IP prefix and return 400 on garbage. Flagged by code-reviewer during PR #357 review.
- 2026-04-10 [server] `ListSecurityEvents` interpolates user-supplied `username` and `ip` into LIKE patterns without escaping `%` or `_`. GORM parameterizes so it's not SQL injection, but admins searching for literal `%` in a username will get a wildcard match instead. Add a `%`/`_` escape pass. Flagged by code-reviewer during PR #357 review.
- 2026-04-10 [server] Security event type catalog is duplicated in three places: Go consts in `server/internal/db/models.go`, the hand-maintained list returned by `GetSecurityEventTypes` in `server/internal/api/security_event_handler.go`, and the TypeScript union in `web/src/types/api.ts`. Consider having `GetSecurityEventTypes` iterate a slice declared alongside the consts in `models.go` so adding a new type only touches one place on the backend. Flagged by code-reviewer during PR #357 review.
- 2026-04-10 [server] When `SecurityEvent.Metadata` JSON fails to parse on read (legacy write, manual DB edit), the response silently drops the field. Log at `slog.Warn` with the event ID so an admin can investigate, and consider returning the raw string in an escape-hatch field like `metadataRaw`. Flagged by code-reviewer during PR #357 review.
- 2026-04-10 [web] `TableRowSkeleton` uses `px-4 py-3` but admin tables (e.g. security-events-table, user-table) render real rows at `px-5 py-3`. Causes a one-column horizontal jitter when the skeleton resolves to data. Either add a `padding` prop to the skeleton or align real rows to `px-4`. Flagged by ui-agent during PR #357 review.
- 2026-04-10 [web] `SecurityEventBadge` in `web/src/features/admin/components/security-event-badge.tsx` has a dead fallback branch for unknown event types — the TypeScript union `SecurityEventType` prevents it from ever being hit. Either remove the dead code, or weaken the prop type to `string` so the fallback becomes a genuine defensive path for when the backend ships a new event type ahead of the UI. Flagged by code-reviewer during PR #357 review.
